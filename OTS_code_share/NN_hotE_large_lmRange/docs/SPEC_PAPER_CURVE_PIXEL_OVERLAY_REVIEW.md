# SPEC：论文灰色曲线取点叠图审查

日期：2026-09-16。范围：只展示此前 Fig.1(a/b/c) 位图取点，不重新定位图轴、拟合或修正坐标。

## 1. Requirements

用户需要直接看见旧算法在三幅位图上选中了哪些像素，以审查遮挡及误选。保留原图，同时分别显示全部灰色候选像素与最终中位数位置；不把通过阈值筛选等同于识别正确。所有产物写入独立的`outputs/ots_experimental_fits/pixel_selection_review_20260916/`，已有拟合及取点产物不变。

## 2. Design

四个普通函数构成独立线性审查脚本。直接读已导出的`figure1.png`，重放旧脚本的 RGB 条件、蓝线搜索限制和中位数选择，与已保存 NPZ 的 pixels 逐点比较。截取 a/b/c 的原始位图区域并用最近邻放大，叠加标记，不插值或连接取点。分别输出最终取点图及“原图/候选像素/最终取点”三栏对照图。

绿色空心圈表示最终中位数恰好落在候选像素上；橙色叉表示中位数没有落在某个候选像素上（包含半像素坐标），只反映算法取值性质，不自动判定为错误。候选图用绿色标出原始像素。保存每个点的原生位图坐标、所在列全部候选及中位数性质，统计没有输出点的扫描列。

`load_review_inputs(repo: Path) -> tuple`
```text
读取原位图、旧脚本及三份已保存的 pixels 数组
保存输入哈希，返回位图、显式面板裁剪/扫描范围和旧取点
```

`replay_selection(rgb: ndarray, xstart: int, xend: int) -> dict`
```text
逐列按原规则定位蓝色像素，y限制为[140,530)
在蓝色像素中位位置±70像素内筛选灰色像素，y限制为[140,532)
保存全部候选；有候选则取y中位数，没有则记录缺失
记录中位数是否是实际候选像素，返回候选与最终坐标
```

`write_panel_review(source: Image, panel: dict, replay: dict, output_dir: Path) -> dict`
```text
从原合图裁剪对应面板，保留原坐标轴、曲线和文字
输出原图、候选像素图和最终取点叠图，最近邻放大2倍
添加独立标题区、颜色图例及数量，不连接取点
写最终叠图PNG、三栏对照PNG和逐点JSON；返回产物与统计
```

`main() -> int`
```text
加载输入，逐面板重放规则并与保存pixels逐点严格相等核验
生成三组审查图；回读PNG尺寸及输入哈希
写审查说明、输出哈希和完成状态
```

## 4. Acceptance Criteria / Tests

- 三个面板重放所得最终坐标与旧 NPZ 的 pixels 完全相同。
- 原生像素坐标到裁剪及2倍放大图的映射一致，不连接缺失列。
- 读者能辨认原蓝/粉曲线、候选像素和最终取点；文字明确筛选不等于真值。
- 原图、旧取点NPZ和旧算法文件哈希不变；三份最终叠图及三栏对照可打开。
- 只增补本次审查产物与说明，不修改原拟合、数据、图轴标定或配准结果。
